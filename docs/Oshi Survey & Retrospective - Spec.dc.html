Oshi Survey & Retrospective

UI design spec & Claude Code implementation guide
Week 4–6 SUBJ_INPUT POST_SESSION orchestrator/agent.py

Source of truth is the prototype Oshi Survey & Retrospective.dc.html. This document specifies its screens and tells Claude Code how to integrate it into the existing clarity-loop repo (vanilla-JS frontend + FastAPI WebSocket backend). Strategy: copy the prototype's markup, styles, and content constants verbatim; let Claude Code do the integration wiring.

1 · What this is

Two Oshi-guided flows that bracket a regulation session — the parts of the state machine that were stubbed in Weeks 4–6:

  • Survey (pre-session) — Oshi meets the player and gathers subjective state before a game: sensation → intensity → body → emotion → offering. This is the SUBJ_INPUT input the orchestrator needs.
  • Retrospective (post-session) — after the game returns, Oshi re-reads intensity, witnesses the shift, and offers one contemplative question: r_intensity → reflection → complete. This is POST_SESSION.

Both are voiced by Grandmaster Oshi (the corner portrait + caption). Every line is scripted for instant paint, then optionally upgraded to a live Claude Haiku line. The game itself is out of scope — the prototype's session screen is a stand-in for game1.html / game2.html.

Design invariants (do not violate). Calm technology — never interrupt. Phenomenological, never clinical. Oshi speaks in lowercase, max two sentences. The forbidden-word list in the persona is a hard filter. Ambiguity over precision: intensity is a 1–10 felt ring, never a labelled slider.

4 · Per-screen specs

All copy (instructions, scripted lines) comes verbatim from the prototype constants INSTRUCTIONS and SCRIPTED. Below is the behaviour Claude Code must preserve.

4.1 · welcome

  • Eyebrow "with grandmaster oshi" · title CLARITY LOOP (Georgia, 46px, 8px tracking) · italic tagline · glass Enter button.
  • Enter → sensation.

4.2 · sensation

  • Wrapping row of chips from CHIP_WORDS = tightness, heavy, jittery, pressure, numbness, activated, spacious, cold, plus an other… chip that opens a centred text input (Enter commits).
  • Selected chip: powder-purple fill + glow (chipOn). Auto-advance on select.
  • Chip→rule normalization (small alias map). Four chips match RuleBasedOrchestrator._select() keys directly — tightness, pressure, numbness, cold. The remaining rule keys are buzzing/tingling, reached via jittery→buzzing. Also alias heavy→pressure. activated and spacious have no somatic rule and pass through as free-text only (they still colour the Oshi prompt). Send the aliased token to the rules; keep the original word for Oshi's narration. Omkar to validate in Week 4 testing.

4.3 · intensity & r_intensity (shared)

  • 340px circle; drag outward from centre grows a glowing ring. Distance → value 1–10 (_setRing): v = round(1 + clamp(dist/R)*9), R = radius − 18.
  • Ring px = 66 + v*22; glow scales with v. Pointer capture; auto-advance ~760 ms after pointer-up.
  • Same component both times — field switches via _ringField() (intensity vs intensityAfter).

4.4 · body

  • SVG humanoid silhouette (single gradient path + glow filter). Invisible tappable regions layered over it: head, throat, shoulders, chest, belly, core, arms, legs, feet.
  • Selected region fills rgba(152,120,232,0.5) + drop-shadow glow; italic label appears below ("the chest"). Copy the entire <svg> block verbatim — the path + ellipse/circle coordinates are hand-tuned.

4.5 · emotion

  • Geoffrey Roberts feeling wheel — 7 cores → mids → tertiary leaves, built by _buildWheel / _sector / _seg (data in FWHEEL). 82 leaves, radii [70,210,300,388], cx/cy 400.
  • Tap any segment → selects that word (stores emotion, emotionKey, core, ring); selected segment gets a 3.5px white stroke. Auto-advance ~660 ms.
  • Critical: wheel labels are real SVG <text> nodes built via React.createElement (wheelLabelsEl) — a templated hole inside <text> renders no glyphs. In vanilla port, create the <text> elements with document.createElementNS. Copy all geometry helpers verbatim.

4.6 · offering

  • Two cards from PATHS: phoenix ascent (grounded & relaxed → game1) and grandmaster's count (reset mind & focus → game2). Title / goal / italic description. Select → session.
  • This is the intervention choice. In the real app, replace session with a redirect to /game1 or /game2 carrying the survey payload (see §6).

4.7 · session (replace with real game)

  • Prototype: breathing orb + "i have returned" button + a simulated capture (_makeSession fabricates breath/restlessness before→after). Delete the simulation. Real deltas are path-dependent:
    • game1 (phoenix ascent) — CV pipeline captures breath + restlessness over the session window → physiological deltas + intensity delta.
    • game2 (grandmaster's count) — no physiological capture → intensity delta only.

4.8 · reflection

  • Optional before→after ring shift visual (showShiftVisual prop). Eyebrow "a question to sit with" → large italic contemplation question → breathing dot → "return to the forest".
  • Reflection line + question come from a single Haiku call returning two parts split on ||| (see §7); scripted fallbacks live in _makeReflection.

4.9 · complete

  • "until the next stillness" + "begin again" (resets all answers). On entry, persist the session.

Oshi portrait & caption (persistent)

  • Fixed bottom-left 116px round portrait, glow-pulse ring; image swaps per screen (map in portraits). Caption = current Oshi line in italic Georgia with typewriter caret.

The protocol is already sketched in main.py. Implement these types.

  "body_region": "chest", "emotion": "anxious",
  "emotion_core": "Fearful", "time_of_day": "auto" }

  "path": "game1", "intensity_post": 4 }
// path === "game2" carries no breath/restlessness — intensity_post only

Server → Client

{ "type": "oshi_line", "screen": "sensation", "text": "…", "req_id": 12 }

{ "type": "intervention", "id": "extended_exhale",
  "params": {...}, "reasoning": "…", "source": "agent" }
// "reasoning" matches OrchestratorResult.reasoning AND main.py's
// documented protocol — no field rename anywhere. "source" is
// "agent" (Haiku) or "rules" (fallback).

{ "type": "reflection", "line": "…", "question": "…" }
  • subjective_input → store on the connection, feed orchestrator.recommend(...), and (offering screen) reply intervention.
  • session_complete → compute before→after deltas by path: game1 = intensity delta + CV breath/restlessness deltas (from the state model); game2 = intensity delta only (no CV). Attach an available_signals list to the reflection request so the narrator knows what it may reference (§7). Reply reflection, persist to backend/db/session.py (Week 6).
  • oshi_line is the live-narration channel: frontend sends the current screen + gathered state, backend returns Oshi's line (§7). req_id lets the client drop stale replies — mirror the prototype's _reqId guard.

6.1 · Orchestrator contract (what recommend() actually takes)

The offering screen's subjective_input is the exact argument set for the existing AgentOrchestrator.recommend() — map the survey fields onto its signature, don't invent a new one. Enums below are the only values the code branches on; anything else falls through to a state-based default.

recommend() argSurvey fieldValues the code acts on
physio_statefrom state model classify(), not the surveyelevated · settling · settled · dissociated · unknown. game2 has no CV → expect unknown; recommend() must still work subjective-only.
emotionemotion (wheel leaf)free — carried into narration, not branched on by rules
body_regionbody_regiononly head · throat · chest drive branches; shoulders/belly/core/arms/legs/feet hit no rule → default
sensations[sensation] — the aliased token (§4.2)tightness · pressure · buzzing · tingling · numbness · cold
intensityintensity 1–10passed through; not branched (available to Haiku)
session_historyretrospective onlySessionHistory(interventions_tried=[{id, pre_intensity, post_intensity}]). Agent-only — RuleBasedOrchestrator.recommend() takes just 5 args and the agent's fallback call drops session_history + time_of_day. Don't rely on them surviving a fallback.
time_of_day_circadian() outputstring tone hint; default "day". Compute server-side (or have the client send its _circadian() string, not the literal "auto") — recommend() won't interpret "auto".
  • Two independent fallbacks — don't conflate them. (a) Intervention selection: AgentOrchestrator.recommend() tries Haiku, falls back to RuleBasedOrchestrator on any error or TIMEOUT_S (3 s). (b) Oshi narration: oshi_line/reflection fall back to the scripted SCRIPTED/_makeReflection lines (§7). Different failure paths, different fallbacks.
  • RuleBasedOrchestrator._reason() already returns lowercase, phenomenological, on-voice lines per intervention — reuse them verbatim as the rules-path reasoning; no rewrite needed.
  • Cooldown: _last_intervention prevents the same intervention twice in a row — preserve it across the connection, not per-request. (Note: it lives on RuleBasedOrchestrator; the agent path only gets it via fallback, so the agent path needs its own cooldown check if Haiku is choosing.)
  • ⚠ Field name is reasoning everywhere — do not introduce narration. OrchestratorResult has fields intervention_id, params, reasoning, source, and main.py's documented intervention message already uses reasoning. But agent.py's own Week-5 sketch is self-contradictory: its prompt asks Haiku for JSON {"narration": …}, then does OrchestratorResult(**result, source="agent") — which raises TypeError (narration is not a field). When implementing _call_haiku, either prompt Haiku to return reasoning, or remap result["reasoning"] = result.pop("narration") before constructing the result. Keep the wire field reasoning too.
  • Two Haiku call sites, not one — keep them separate. (a) _call_haiku() already stubbed in agent.py — the intervention selector, returns {intervention_id, params, reasoning}, called inside recommend(). (b) _oshi_line() new (§7) — the per-screen survey narration voice, returns a plain string. Same client, same persona tone, different jobs and return shapes.

7 · Oshi voice — scripted fallback + Haiku upgrade

Two layers, exactly as the prototype: paint the scripted line instantly, then replace it if a live line arrives. Never block the UI on the API.

Already built — wire, don't rewrite. The entire server-side narration layer described in this section (persona system prompt, per-screen prompt assembly _contextFor, the ||| reflection, the forbidden-word guardrails, and the scripted floor) is now implemented as the backend/orchestrator/oshi/ package — one class, OshiNarrator. Do not hand-write _oshi_line() or a second Haiku call for narration. Instantiate OshiNarrator() per connection and call .line(screen, subj, req_id) / .reflection(session, subj), sending .to_message() — see that package's README.md "Wiring" + "Integration checklist". The code sketch below is kept as design rationale for what the package does. agent.py's only remaining live-Haiku job is the intervention selector (_call_haiku, §6.1), which is a different return shape.

Layer 1 — scripted (ship first)

  • Bake SCRIPTED + INSTRUCTIONS into oshi_flow.js. On screen enter, show the scripted line immediately. This is the guaranteed floor — the flow is fully usable with zero API.
  • Reflection fallbacks (before/after comparison) live in _makeReflection; copy them.

Layer 2 — live Haiku (upgrade)

Move the Anthropic call server-side (the prototype's window.claude.complete is prototype-only). In agent.py:

import os, anthropic
self._client = anthropic.Anthropic(api_key=os.environ["ANTHROPIC_API_KEY"])

def _oshi_line(self, system, user, max_tokens=120):
    msg = self._client.messages.create(
        model="claude-haiku-4-5",
        system=system, max_tokens=max_tokens,
        messages=[{"role": "user", "content": user}],
    )
    return msg.content[0].text.strip()
  • system = the PERSONA constant (copy verbatim — it holds the lowercase rule, 2-sentence ceiling, and forbidden-word list).
  • user = per-screen context. Copy _contextFor(screen) + _circadian() verbatim; they already assemble "information gathered so far" + environment tone.
  • Post-process every line with _clamp2() (keep ≤ 2 sentences). Keep the typewriter reveal on the client.
  • Reflection: one call, prompt asks for two parts split by ||| → reflection line + contemplative question. Parse and clamp both (see _makeReflection). Condition the prompt on available_signals: for game1 Oshi may witness the felt and bodily shift (breath softened, stillness grew); for game2 Oshi speaks only to the intensity shift and must not invent or imply any breath/body reading it never measured. Build the "what changed" context from only the deltas present for that path.
  • Timeout 3 s (AgentOrchestrator.TIMEOUT_S); on any error/timeout → keep the scripted line. Never raise into the socket loop.
  • Add ANTHROPIC_API_KEY to .env.example and anthropic to backend/requirements.txt.
The persona is load-bearing. Do not paraphrase PERSONA, and do not relax the forbidden-word list (anxiety, stress, heart rate, data, metric, slider, fix, optimize…). If a returned line trips the filter, fall back to scripted rather than shipping it.
